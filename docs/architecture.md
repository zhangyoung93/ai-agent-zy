# 项目架构说明

## 目标

以 DeepSeek（OpenAI 兼容接口）为底座，搭建一个可扩展的企业级 AI Agent 项目骨架，
为后续学习「工具调用 / RAG / 多 Agent 编排」提供统一的基础设施。

## 分层结构

```
┌─────────────────────────────────────────────┐
│  cli.py / examples        （入口层）          │
├─────────────────────────────────────────────┤
│  agents/                  （Agent 层）        │
│    base.py   Agent 抽象基类                  │
├─────────────────────────────────────────────┤
│  tools/                   （能力层）          │
│    registry.py  工具注册表 + @tool 装饰器    │
├─────────────────────────────────────────────┤
│  llm/                     （模型层）          │
│    client.py   DeepSeek 客户端封装           │
├─────────────────────────────────────────────┤
│  config.py / logging.py   （基础设施层）      │
└─────────────────────────────────────────────┘
```

## 各层职责

| 层 | 职责 | 演进方向 |
|----|------|---------|
| 入口层 | CLI 命令、示例脚本 | 后续可加 FastAPI Web 服务 |
| Agent 层 | 定义 Agent 统一接口 `run(task) -> str` | 实现 ReAct 循环、多 Agent 协作 |
| 能力层 | 注册可被 LLM 调用的工具 | 生成 OpenAI Function Calling 的 tools 参数 |
| 模型层 | 统一模型调用（多轮对话、单轮补全） | 加流式输出、重试、成本统计 |
| 基础设施层 | 配置（pydantic-settings）、日志 | 结构化日志、配置热更新 |

## 关键设计决策

1. **src 布局**：`src/ai_agent_zy` 作为唯一源码目录，避免 import 歧义，便于打包发布。
2. **配置集中管理**：所有配置项在 `config.py` 的 `Settings` 中声明，类型安全、启动即校验；
   密钥只走环境变量 / `.env`，绝不写进代码。
3. **依赖最小化**：核心依赖仅 `openai` + `pydantic` + `pydantic-settings`，
   后续按需引入 LangGraph、向量库等。
4. **测试优先于集成**：单元测试离线可跑（不依赖真实 API），CI 中自动执行。

## 下一步路线

1. 工具调用（Function Calling）：把 `tools/registry.py` 转成 OpenAI tools 参数，实现真正的 Agent 循环。
2. RAG：引入向量数据库 + 检索。
3. 多 Agent：基于 `agents/base.py` 扩展协作编排。
